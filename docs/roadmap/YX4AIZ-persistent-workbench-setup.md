# Configure a persistent home and Herdr binding

## Why

The user wants one durable editor workbench beside Ghostty/Herdr. Moving its first root
restarted extensions in the pilot; automatic following must not repeat that disruption.
A chosen personal home also supports optional shared Foam navigation.

## Scope to shape

- Explicitly enable one saved native `.code-workspace`, choose home and a local Herdr
  endpoint, and explain any deliberate first-root reconfiguration before applying it.
- Keep home first, protect unrelated windows, and pause rather than silently repair a
  displaced home. Respect Workspace Trust and same-filesystem boundaries.
- Define binding persistence, pause/resume, connection feedback and duplicate-controller
  handling appropriate to the accepted release.
- Explain consent for server-driven additions when attachment is introduced; follow-only
  setup must not implicitly enable later membership mutation.

No parallel folder manifest, note migration or automatic Foam configuration. See
[product direction](../../PRODUCT.md). Whether the first slice requires a setup wizard
or explicit configuration is unresolved; native settings/commands are sufficient in
principle, not a commitment to a particular interface.
